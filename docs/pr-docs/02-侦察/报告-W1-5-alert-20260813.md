## 二、taiji-server RPC 域设计

### alert.send — 提交告警（三通道路由 + AlertStore 登记）

```
params: {
  level:   "heartbeat"|"warn"|"error"|"critical",  // 白名单，非法 → -32602
  title:   String,                                 // 必填
  body:    String,                                 // 必填
  source?: String,                                 // 缺省 "rpc:alert"
  dry_run?: bool,                                  // 缺省 false
}
result: { alert_id, level, source, simulated, dispatched, channels }
```

- 路由表（taiji-alert dispatch）：Warn→desktop / Error→desktop+feishu / Critical→desktop+feishu+email / Heartbeat→feishu
- **副作用红线**：`dry_run=true` 或未配置 webhook → `simulated:true` + `channels:[]`（零真实投递，显式降级不虚构）；真实投递仅 `dry_run=false` 且 webhook 已配置时发生
- **与 risk.alerts 衔接**：告警同时写入 `AlertStore`（level 取 AlertLevel 小写），可经 `risk.alerts` 查询 / `risk.alert.ack` 确认——同源记录面，互不冲突

### alert.heartbeat.record — 心跳活动登记

```
params: {}
result: { ok: true, interval_min: u32, last_recorded_at: RFC3339 }
```

- `HeartbeatMonitor.record_activity` 重置内部计时；interval_min 来自 taiji-alert AlertConfig（默认 30min）
